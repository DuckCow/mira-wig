# 협업 프로토콜 (Claude × Codex × 사람)

> **이 문서는 "어떻게 일하나"(규칙·방식)다.** "지금 어디까지 왔나"(상태·결정·다음)는 별도 **핸드오프 문서**가 담는다.
> **사용법**: 새 개발 채팅을 열 때 이 문서 + 최신 핸드오프 문서를 함께 붙인다. Codex는 `AGENTS.md`로 이 규칙 대부분을 자동 적용받는다(겹치는 항목은 AGENTS.md가 코드 측 SSOT).
> **개정 이력**: v2 (2026-07-06) — 결제 코어 재작성 반영: "STRICT 코어 보존(불변)" 규칙을 "변경 규율 + 동결 존"으로 재정의(핵심 엔지니어링 규칙 참조, 코드 측 상세는 `AGENTS.md` §4.5·§8).

---

## 역할

- **사람**: 오케스트레이터. 우선순위·사업 판단·최종 결정. 커밋 실행(수동).
- **Claude**: 설계·검수·프롬프트 작성. **코드를 직접 쓰지 않는다.** 전체 궤적·결정 근거·단계 일관성을 본다.
- **Codex**: 구현·정찰(코드 탐색)·런타임 검증. `AGENTS.md`를 따른다. 실제 시그니처·기존 패턴·무엇이 이미 있는지를 본다.

핵심 비대칭: **Codex는 코드를 보고, Claude는 설계·맥락을 본다.** 협업의 가치는 이 비대칭을 합치는 데서 나온다.

---

## 단계 루프 (모든 STRICT / 되돌리기-비싼 작업)

```
정찰(read-only) → 설계 잠금 → 격리 빌드 → 검수 → 격리 커밋
```

1. **정찰 (read-only)**: 빌드 전, Codex가 코드 변경 없이 현 사실을 보고. 시그니처·기존 패턴·무엇이 비었는지. *가정하고 빌드하지 않는다.*
2. **설계 잠금**: 정찰 결과로 Claude가 설계를 확정. 갈림길은 코드 사실에 근거해 정한다.
3. **격리 빌드**: **한 단계 = 한 관심사.** 기능과 규칙 변경을 섞지 않는다. 스키마·코어·UI를 한 커밋에 뭉치지 않는다.
4. **검수**: Claude가 결과를 본다(아래 검수 기준).
5. **격리 커밋**: 단계마다 즉시, 논리 단위로 분리. 미커밋으로 쌓아두지 않는다(복구지점 = 안전).

## 교차검토 판정 — 언제 Claude·Codex가 서로 검토하나

빌드 전에 다른 에이전트의 검토를 받을지 정하는 기준:

> **(a) 되돌리기 비싸거나 STRICT 코어이고, + (b) 틀렸는지 *지금 내 시야로* 알 수 없을 때 → 받는다.**
> **단순하거나, 가역적이거나, 자기 영역(코드 사실은 Codex / 설계·일관성은 Claude)이면 → 그냥 한다.**

**(a) 판정 주의 — 스텝 강도는 스텝 이름이 아니라 *건드리는 대상별*로 본다.** "이번은 UI 스텝이라 NORMAL"처럼 뭉뚱그리면, 그 안에 섞인 STRICT 조각(예: 결제 멱등키 생성, 금액 계산 공유)을 놓친다. NORMAL 스텝이어도 그 조각만은 STRICT 강도(정찰 선행·행동 테스트·런타임)로 다룬다.

**받을 때의 방식**:
- **좁혀 묻는다.** 열린 "개선점 있어?"는 금지 — 스코프를 부풀리고 과설계를 부른다. 대신:
  - *정합성*: "이 가정이 코드와 맞나" (계획 X → 실제 Y)
  - *접근법*: "이 설계가 이 코드베이스/구조에서 최선인가" (현 계획 vs 대안 + 근거)
- **검토 결과는 *입력*이지 최종 결정이 아니다.** 받은 제안을 "MVP 규모에 맞나 / 단계 규율(작게·격리)에 맞나"로 거른다. 두 시야를 합쳐 사람(또는 Claude)이 정한다.

**받을 케이스 예** (과거 세션 실제): 포트 시그니처 확장, finalizer 첫 수정, 검증 추상화(helper) 설계, "내가 코드 못 봐서 가정한 인자 모양".
**안 받을 케이스 예**: 줄 정리 같은 위생, 이미 정찰한 영역의 사소한 후속, 가역적 NORMAL UI.

## 핵심 엔지니어링 규칙

- **"verify 초록 ≠ 작동."** STRICT 코어·실거래 경로는 *런타임*으로 검증한다(브라우저 클릭, Network status, DB 조회). 타입체크·테스트 통과만으로 "된다"고 하지 않는다.
- **규칙(헌법) 변경은 기능 커밋과 분리** + 변경 전 합의. 줄 한도·STRICT 정의 같은 프로젝트 규칙을 기능 작업에 묻지 않는다. 한도를 만나면 **쪼개거나 압축**하지, 한도를 올리지 않는다(카테고리 차원 근거가 논증됐을 때만 — 예: 테스트는 명시성 우선이라 줄 한도 면제).
- **외부 API 사실은 공식 문서만.** 2차 블로그 금지. 인용 시 출처 명시. 불확실하면 추측 말고 문서 확인.
- **커밋 규율**: 단계마다 즉시, 논리 단위로 분리. 기능/스키마/규칙을 한 커밋에 섞지 않는다.
- **STRICT 코어 변경 규율 + 동결 존 (v2 재정의)**: 핵심 트랜잭션(신 결제 finalizer 등)은 "불변"이 아니라 **"STRICT 루프(정찰 → 설계 잠금 → 행동 테스트 → 런타임 검증) 없이는 변경 금지"**다 — 변경은 최소 단위로, 원자성·불변식은 행동 테스트로 고정한다. **구(레거시) 결제 코드는 별도 지위: 동결(read-only, 대체 중)** — 수정·정리·"지나가며 개선" 금지, 예외는 사람 명시 승인(운영 장애 대응 한정) + 단독 격리 커밋, 신 코드에서 구 코드 import 금지. 대상·글롭·해제 절차의 상세는 `AGENTS.md` §4.5(코드 측 SSOT), 신 코어 규칙은 §8.
- **코드를 못 보는 쪽(Claude)은 단정 대신 정찰로 위임한다.** Claude가 코드 사실을 모르는 채 "이렇게 구현하라"고 단정하면, 그 지시가 실행 맥락(트랜잭션 시점·데이터 신선도·격리)과 어긋나도 못 잡는다. 그런 지점은 "이걸 정찰해 판단하고 근거를 보고하라"로 열어 위임한다 — Codex가 능동적으로 근거를 대면 어긋남이 빌드 전에 드러난다. ("재사용하라"류도 같은 값이 *같은 시점·같은 데이터*로 쓰이는지 다르면 틀린다 — 정의는 공유, 접근은 분리.)
- **STRICT/NORMAL/FROZEN 존, 줄 한도, 추상화 계층의 SSOT는 `AGENTS.md`**(와 `eslint.config.mjs`). 충돌 시 그쪽을 따른다.

## 검수 기준 (Claude가 결과를 볼 때)

- **"왜"를 확인한다.** 에이전트 보고를 결론만 받지 않는다 — 수치/동작이 왜 그런지(예: 테스트 카운트가 왜 그대로인지, 왜 이 상태로 전이했는지) 짚는다.
- **STRICT 코어는 diff를 눈으로.** 보고가 "불변"이라 해도, 되돌리기 비싼 코어(finalizer 등)는 직접 본다. **동결 존(FROZEN)은 diff가 비어 있어야 정상** — 동결 존에 diff가 있으면 그 자체가 검수 실패 신호다(사람 승인 예외 제외).
- **런타임 증거를 요구.** STRICT/실거래는 "무엇을 클릭했고 어떤 status를 봤고 DB가 어떻게 변했나"를 보고에 요구한다. (자동화가 막히는 단계 — 예: 카드사 보안 키패드 — 는 사람이 1회 수동 검증.)
- **회귀 신호.** 기존 테스트 수가 유지/증가하는지로 회귀 없음을 1차 확인하되, 그것에만 의존하지 않는다.

## 새 개발 채팅 시작 패턴

1. **이 문서 + 최신 핸드오프 문서**를 붙인다 (규칙 + 맥락). 핸드오프엔 *결정의 근거*와 *다음 계획*이 담겨 있어야 한다(코드 정찰로는 복원 안 되는 것들).
2. 핸드오프가 가리키는 **다음 작업의 정찰(read-only)**부터 시작한다 — 핸드오프로 "무엇을 왜"는 알아도, *그 시점 코드의 정확한 시그니처*는 정찰로 갱신해야 빌드가 안 깨진다.
3. 정찰 → 설계 잠금 → 격리 빌드 → 검수 → 커밋 루프로 진행.

> Codex 쪽은 `AGENTS.md`가 자동 적용되므로 별도 첨부 불필요. Claude 쪽은 이 문서로 충분하되, 필요 시 `AGENTS.md` 전문을 붙인다.

## 적용 범위 메모

이 프로토콜은 **개발 / 에이전트 협업 채팅**에만 적용된다. 같은 프로젝트라도 비개발 채팅(리서치, 다른 도구 협업, Claude 단독)에는 적용하지 않는다 — 그래서 **프로젝트 지침(Project Instructions)에 넣지 않고**, 개발 채팅에서 이 문서를 *붙여서* 끌어온다. 일반 사고 원칙(되돌리기-비싼 결정은 근거 점검 후 진행, 남의 결론은 검증해 입력으로)만 Claude User Preferences에 둔다.
