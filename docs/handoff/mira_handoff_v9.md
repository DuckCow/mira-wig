## 4. 핵심 의사결정 (v9 — 코드론 안 보이는 것)

> v8까지의 결정(4-1~4-5 등)은 이전 핸드오프 유지. 단 **결제 코어 관련 결정은 컷오버까지만 유효**한 것이 많다 — §5·§6 재판정 참조.

**4-6. 재작성 채택 근거**: 갭이 조각이 아니라 골격(주문 생성 시점·동시성 중재·유니크 구조·MR 시점) — 점진 리팩터는 STRICT 코어를 여러 번 여는 최악 경로. 인양 가치는 코드가 아니라 지식으로 이전(문서 경유, 공식 문서 재확인 후).
**4-7. B′ 근거**: 동명 모델 공존 불가 → 어차피 컷오버 강제 → 이동·병행이 사려던 가치를 컷오버가 대체. 컷오버~Stage B 사이 결제 플로우 부재는 수용된 비용(실사용자 없음) — **단 §7의 토스 심사 상호작용 확인 전까지 조건부**.
**4-8. 클린 컷 근거·파급**: 실배포 없음(사람 확정). 컷오버의 테이블 drop 마이그레이션은 `migrate deploy` 경유로 프로덕션 DB에도 적용 — go-live에 "프로덕션 DB 행 폐기 인지" 항목 추가 필요(§7).
**4-9. §6-5 승계**: v8의 B/C1/C2는 정책으로 흡수 — B ⊂ CORE-1(Full C, 단 metadata 매칭이 아니라 **CheckoutSession 엔티티**로 — v8이 예상한 것보다 강한 해법: "결제 성공→주문 생성 실패" 창은 세션 스냅샷+멱등+망취소+대사가 담당), C1 = CORE-5, C2 = B2 완료 트랜잭션 소속. **v8의 "재설계지 신축 아님" 서술은 이 결정으로 폐기.**

## 5. ★ 안전 전제 — 지위 변경 (반드시 읽어라)

v7 §5 네 불변식 + v8 §5-5는 **레거시 코드의 live invariant로서 컷오버까지만 유효**하고, 컷오버로 코드와 함께 소멸한다. 단 두 가지가 살아남는다:

1. **지식으로**: 인양 정찰이 §5 불변식들을 구현-중립 명세로 번역해 `docs/payment_policy/legacy_salvage_notes.md`에 보존한다(신 코어 C1 하네스·§7.1 환불 설계의 입력). **동결 존이라 그 전까지 이 불변식들을 "개선"하러 들어가지 마라.**
2. **구조로**: 5-5의 통찰("완료 시맨틱은 provider×경로 단위에서 갈린다 — PayPal eCheck/PENDING")은 정책의 **미병합 diff**(§8.2 경계 재정의·PG-1 라우팅 표 완료-시맨틱 열)가 정확히 구조화한다. 레거시 PayPal strategy가 PENDING을 조용히 무시하는 것(정찰 확인)도 같은 자리 → **정책 v5 병합이 컷오버 전 할 일인 근거**.

## 10. 작업 방식 (요약 — 상세는 protocol v2 + AGENTS v3)

- 루프·교차검토·verify≠작동·커밋 규율·정찰 위임: v8 §10 유지.
- **STRICT 코어 규칙 갱신(구판 인용 금지)**: "로직·순서 불변"이 아니라 — 신 코어는 **"STRICT 루프 없이 변경 금지"**, 레거시는 **동결(read-only, diff 있으면 검수 실패)**. 출처: protocol v2 + AGENTS §4.5·§8.
- **v9 세션 교훈**:
  - (e) **정찰 보고 2건의 교차 일치**를 검수 근거로 씀(리포를 못 보는 쪽의 검증 수단) — 단 교차 일치 ≠ 실물 확증, 인용 형식(파일:라인)이 재현 가능성을 담보.
  - (f) **push 후 `git status` clean 확인까지가 한 사이클** — "커밋했다" 기억과 HEAD가 어긋난 사건(§3-5). status는 HEAD 대비, rename 탐지는 스테이징 후, reflog가 판정 도구.
  - (g) **문서-디스크 불일치 미해결 플래그**: `payment_policy_*_v2.md`가 디스크에 실존하나 v3·v4 개정 이력은 "v2 건너뜀"이라 기록 — 정책 v5 때 파일 내용 확인 후 이력 문구 정정(§6-1 3번에 포함).
  - (h) **권고의 숨은 전제를 새 정보가 제거하면 승인 후라도 철회·재전개**(이동안 철회 사례 — 승인이 매몰비용이 아님).
- 협업 선호(Profile): 유지 — 옵션 펼치기·전제 풀기·검토 경계·결과물은 입력.
