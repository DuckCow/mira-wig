## 4. 핵심 의사결정 (v10)

**4-10. 컷오버 실행 설계**: 단일 원자 커밋 배제(검수 불능) → **태그 + 2커밋**(코드/스키마). 스텁-삭제 원칙: URL 자산=스텁(웹훅 **503** — 200은 PG에 거짓 성공, 404는 URL 오등록 오인이라 배제), drop 테이블 리더=삭제(list.ts 등 — "읽기라 생존" 인양 판정을 클린 컷 결합으로 뒤집음), 사용자 대면=라우트 유지+본문 스텁. 검수 기준 교체: "테스트 수 유지=회귀 없음"이 삭제 국면에선 역전 — 커밋 메시지에 감소 사유 명시 + "남은 것 초록 + 삭제 목록=명세" 대체.
**4-11. 토스 심사 ↔ 컷오버 창**: 공식 문서 근거로 "심사 = 결제창 호출 확인(테스트 키·클라이언트 연동)" 확인 → 컷오버를 심사에 인질 잡지 않기로. 헤지 2종 상비: ① `pre-cutover` 태그 배포(+스크래치 DB) ② 신 체크아웃에 테스트키 결제창 클라이언트 스텁. **온보딩 채널 질문 큐**: 연동 방식 교체 시 재확인 절차 / 크로스보더 상품 추가 요건.
**4-12. cart KRW 표시 버그 승격**: `WigVariant.price`(KRW 하위호환)를 현재 마켓 통화로 포맷하는 경로 — "심사 시 가격 표기 불일치 = 반려 사유 빈발"(공식 블로그) 근거로 표시 결함 → **심사 반려 리스크**로 승격. 비동결·비결제라 즉시 수정 가능, 우선순위는 사람 판단.
